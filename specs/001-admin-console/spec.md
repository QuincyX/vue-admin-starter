# Feature Specification: 管理后台骨架（鉴权 · RBAC · 总览 · 日志 · 通用列表）

- ID: `001`
- Status: `Verified`
- Created: `2026-11-22`
- Supersedes: `none`

## 问题与目标

现有 `vue-webapp-starter` 是面向个人效率场景的工程模板，缺少后台产品常见的骨架能力：权限分层、受保护的后台壳、运营指标、可审计的操作记录，以及一套能复用的列表/表格范式。团队每接一个后台项目都要重新搭这些内容。

目标：产出一个**可运行的 Web 管理后台起始模板**，把上述能力沉淀为框架能力，并用两个真实模块（成员管理、操作日志）证明它们可复用。

## 非目标

- 不实现移动端布局与移动端导航（桌面端优先是产品决策）。
- 不实现多语言；界面统一简体中文。
- 不做自助注册、第三方登录、找回密码邮件流。
- 不做真实后端、数据库、消息队列；演示数据保存在浏览器或本地 mock 服务。
- 不实现完整的国际化日期/数字格式、无障碍移动端手势。

## 用户故事

### User Story 1 - 登录与路由拦截 (Priority: P1)

作为后台用户，我希望未登录时被拦到登录页、登录后回到原目标页，并且刷新不会掉登录态。

**为什么是 P1**：没有它，任何后台页面都无法安全暴露。

**独立验证方式**：匿名访问深链 → 登录 → 回到该深链；刷新后仍在同一页。

**验收场景**：

1. **Given** 未登录，**When** 访问 `/audit?outcome=failure`，**Then** 跳转 `/login?redirect=/audit?outcome=failure`；登录成功回到该地址。
2. **Given** 已登录，**When** 刷新任意页面，**Then** 会话由 `/auth/me` 恢复，页面不闪回登录页。
3. **Given** 已登录，**When** 在账号菜单退出，**Then** 回到 `/login` 且刷新后仍未登录。
4. **Given** 错误密码，**When** 提交登录，**Then** 表单内显示错误，不跳转。

### User Story 2 - 基于角色的访问控制 (Priority: P1)

作为拥有者/管理员/观察员，我希望看到的入口与可执行的操作与我实际拥有的权限一致；越权访问应得到明确解释。

**为什么是 P1**：后台的第一风险是权限，模板必须给出可复用的正确姿势。

**独立验证方式**：分别用三种角色登录，对照权限矩阵检查导航、按钮、直达 URL 的行为。

**验收场景**：

1. **Given** 观察员，**When** 查看侧边栏，**Then** 不出现「访问控制」；直达 `/access` 得到 403 页面并说明原因。
2. **Given** 观察员，**When** 打开成员管理，**Then** 没有「新增成员」按钮、没有选择框，表格只读。
3. **Given** 管理员，**When** 尝试把成员设为「拥有者」，**Then** 选项不可用且底部说明原因。
4. **Given** 拥有者，**When** 打开 `/access`，**Then** 看到角色 × 权限矩阵与演示账号。

### User Story 3 - 数据总览 (Priority: P2)

作为管理者，我希望在一屏内看到关键指标、趋势、操作分布与系统状态，并能跳到明细。

**独立验证方式**：登录后断言语义化 KPI、三张图表与最近操作列表存在；切换区间后 URL 与图表同步。

**验收场景**：

1. **Given** 已登录，**When** 打开 `/`，**Then** 显示 4 张 KPI 卡、趋势图、操作分布、角色分布、系统状态与最近操作。
2. **Given** 总览，**When** 点击「30 天」，**Then** URL 带 `range=30`，刷新后仍为 30 天。
3. **Given** 最近操作列表，**When** 点击某行，**Then** 跳转 `/audit?detail=<id>` 并打开详情弹窗。

### User Story 4 - 操作日志 (Priority: P2)

作为管理员，我希望按操作类型、结果、日期与关键词检索日志，查看单条详情并导出。

**验收场景**：

1. **Given** 日志页，**When** 选择结果为「失败」，**Then** 列表只剩失败记录且 URL 带 `outcome=failure`。
2. **Given** 日志页，**When** 设置一个无匹配的日期范围，**Then** 显示空状态与「共 0 条记录」。
3. **Given** 一条记录，**When** 打开详情，**Then** URL 带 `detail=<id>`，刷新后仍打开该条。
4. **Given** 拥有者/管理员，**When** 点击导出，**Then** 下载 `audit-YYYY-MM-DD.csv`。

### User Story 5 - 通用表格与列表管理 (Priority: P1)

作为开发者，我希望新列表页只写列定义、筛选与比较器就能拥有搜索、排序、分页、选择与 URL 状态。

**验收场景**：

1. **Given** 成员页，**When** 搜索「陈思远」，**Then** 只剩 1 行，URL 带 `q=`，刷新后仍筛选。
2. **Given** 成员页，**When** 点击「成员」表头，**Then** `th[aria-sort=ascending]` 且 URL `sort=name:asc`；再点一次变降序。
3. **Given** 成员页，**When** 点击下一页，**Then** 范围摘要变为 11–20；`?pageSize=20` 直达时显示 1–20。
4. **Given** 勾选若干行，**When** 执行批量移除，**Then** 行被删除、选择被清空、列表与审计都有记录。
5. **Given** 新增成员，**When** 使用已存在邮箱，**Then** 表单内提示邮箱冲突且不写入。

### User Story 6 - 系统设置 (Priority: P3)

作为用户，我希望管理显示名称、密码、主题与演示数据，并验证后端连通性。

**验收场景**：

1. **Given** 设置页，**When** 切换深色并刷新，**Then** 仍为深色。
2. **Given** 设置页，**When** 修改显示名称，**Then** toast 成功且顶栏名称更新。
3. **Given** 观察员，**When** 打开设置页，**Then** 不显示「恢复示例数据」，显示「需要系统管理权限」。

## 功能需求

- **FR-001**：登录返回 `{ token, user }`，`user.role ∈ {owner, admin, viewer}`。
- **FR-002**：路由守卫实现「恢复会话 → 游客跳转 → 权限 403」三段逻辑，并拒绝外部 `redirect`。
- **FR-003**：权限表是路由、导航、按钮与业务规则的唯一来源。
- **FR-004**：列表的搜索/筛选/排序/分页/每页条数写入 URL，默认值不写入；非法值回退默认。
- **FR-005**：表格提供可访问的排序（`aria-sort`）、选择（`aria-checked` 含 `mixed`）、空状态与加载骨架。
- **FR-006**：总览图表使用 ECharts，按需注册并单独分块；图表提供 `role="img"` 文本摘要。
- **FR-007**：审计动作是封闭枚举；登录、退出、成员增删改、资料/密码修改、导出、重置都会写入。
- **FR-008**：破坏性操作必须二次确认；拥有者账号不可移除。
- **FR-009**：所有数据边界经 Zod 校验；本地数据损坏时回退种子数据。
- **FR-010**：主题支持浅色/深色/跟随系统并持久化；首屏无主题闪烁。

## 边界与异常

- 会话在使用中过期：保留页面与已填内容，用登录弹窗续签并重放被中断的操作。
- 本地存储不可用（隐私模式/配额满）：持久化失败不影响页面可用性。
- 删除后仍存在的选择 id：批量操作前清理，避免对已删除行执行。
- 空列表：区分「无数据」与「无匹配」文案。
- 审计写入失败：吞掉错误，不阻塞领域操作（演示取舍，生产改为服务端事务）。
